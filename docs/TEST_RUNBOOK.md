# Vela: запуск и повторяемая проверка

Дата: 2026-10-28. Базовый мануал: [USER_MANUAL.md](USER_MANUAL.md). Результаты прошлой ручной сессии: [MANUAL-02](agents/reports/MANUAL-02.md). Дополнительные автоматические проверки: [MANUAL-03](agents/reports/MANUAL-03.md).

## 1. Запуск в отдельной базе

Останови прежний launcher через Ctrl+C. Открой PowerShell и выполни:

```powershell
Set-Location 'C:\Users\sanat\OneDrive\Desktop\vela'
$velaRunId = Get-Date -Format 'yyyyMMdd-HHmmss'
$velaTestDb = Join-Path (Get-Location) ".local/test-$velaRunId.db"
$env:DATABASE_URL = 'sqlite:///' + $velaTestDb.Replace('\', '/')
Write-Host "Тестовая база: $velaTestDb"
python scripts/start-dev.py --web
```

Сохрани напечатанный путь: повторный запуск с тем же DATABASE_URL проверяет сохранение; новый путь создаёт чистую ветку. Не запускай второй сервер поверх первого. Открой http://localhost:8081. API address и токен возьми из `.local/dev-connection.txt`; токен не включай в отчёт. Дождись Connect Vela: сообщение READY само по себе не подтверждает сборку экранов.

После остановки верни обычный запуск командой `Remove-Item Env:DATABASE_URL`. Она убирает настройку только из текущего PowerShell, не удаляет файл базы. Следующий обычный `start-vela.cmd --web` использует штатную конфигурацию.

## 2. Автоматические проверки

Запускай из корня проекта, каждую команду отдельно; успешное завершение — код 0.

```powershell
python scripts/check.py
python scripts/generate-contracts.py --check
python evals/run.py --offline
Push-Location apps/mobile
npm run typecheck
Pop-Location
```

Ожидание для текущей версии: backend 215 tests OK; Contract check passed; offline 60/60 PASS; typecheck без ошибок. FAIL в специально созданных негативных примерах внутри backend-тестов допустим только при итоговом OK всего набора. Offline не вызывает настоящую модель.

Для быстрого повторения денежных путей:

```powershell
Push-Location services/api
python -m unittest discover -s tests -p test_journeys.py -v
Pop-Location
```

Ожидание: 31 tests, OK. Запуск этой команды из корня без изменения пути не найдёт пакет vela.

## 3. Начальная фикстура P0

В чистой базе: Enter balance manually. Имя Test User; cash 1000; buffer 100; goal Test reserve; target 1000; saved 0. Plan through — сегодня +30 дней. Добавь Rent 600 на +7 дней, Living 150 на +14, Required debt payment 50 на +21, соответствующие типы rent/living/debt. Включи All bills included и Debts checked. Save balance & bills.

## 4. Что ещё проверить вручную

### U04: отмена плана — отдельная непроверенная ветка

1. P0 → Change amount → 40 → Check amount → Add to my plan.
2. Сверь cash 1000, saved 0, planned 40, free 60.
3. My Plan → Cancel step.
4. Ожидай History Cancelled, отсутствие активного шага, free 100. Повторное открытие не возвращает резерв.

### U06: ухудшение ситуации

1. Новый P0 → запланировать 40, не выполнять.
2. My Plan → + Add bill: Extra 80, срок завтра, other → Save bill.
3. Today: cash 1000, bills 880, planned 40, free −20.
4. My Plan: выполнение старых 40 недоступно, есть пояснение.
5. Cancel step освобождает резерв: free 20, cash 1000, saved 0.

### U07: Remove и Mark paid

1. Новый P0 → добавить Test bill 80 на завтра. Free 20, cash 1000.
2. Remove именно Test bill: free 100, cash 1000.
3. Добавить Test bill 80 снова → Mark paid (−cash).
4. Cash 920, bills 800, free 20. Оплаченный счёт исчез; повторный переход между вкладками не списывает ещё 80.

### U16: ошибки ввода

1. P0 → Choose amount → 12.34 → Check amount: goal 12.34, still free 87.66. Повтори 12,34: тот же результат.
2. По отдельности введи −1, abc, 12.345: сохранение отклоняется, cash/saved/planned прежние. Не нажимай Add для допустимых примеров.
3. В Add bill проверь 0, −1, abc, 12.345; дату 2026-02-30 и дату позже Plan through. Ни один неверный счёт не появляется в My Plan.
4. Верни валидные поля и выйди Back без Save: финансовое состояние прежнее. Отдельно запиши, очищается ли старая ошибка после исправления.

### U17: неполные данные

1. P0 → Edit balance → выключить All bills included → Save.
2. Today требует уточнения, обычное выделение денег недоступно.
3. Подтверди Yes, all included: free 100, предложение снова доступно.
4. Повтори с Debts checked. Неизвестность долгов не должна трактоваться как их отсутствие.

### U18: двойные нажатия

1. Новый P0: два быстрых нажатия Add to my plan для 40.
2. Должен быть один Planned 40; допустима понятная ошибка конфликта. Free 60.
3. Mark done → два быстрых Confirm done: один Completed, saved 40, cash 1000, free 60.
4. На отдельной ветке повтори Save bill и Mark paid. Проверяй число счетов и точное уменьшение cash, а не только исчезновение кнопки.

### U14: экспорт

1. Запиши текущие cash/saved/bills/planned и число операций.
2. Today → Data, AI quota & connection → Export JSON.
3. Проверь, появился ли доступный механизм Share/сохранения. Отмени внешнюю отправку; для проверки достаточно локальной копии.
4. Открой JSON: значения совпадают со снимком, отсутствуют токен подключения, GEMINI_API_KEY и содержимое .env.
5. Если кнопка ничего не делает или Share не поддерживается, запиши FAIL/BLOCKED с браузером; успешный API export не заменяет этот тест.

### U15: удаление — только последним в тестовой базе

1. Убедись по команде запуска, что это отдельная test-*.db, а не demo.db. Сохрани нужный экспорт.
2. Delete all data → Cancel: данные прежние.
3. Когда тестовые записи больше не нужны: Delete all data → Yes, delete all.
4. Вернись Today: пустое состояние; старых операций, долгов, цели и действий нет. Перезапуск не восстанавливает их. Счётчики AI могут сохраниться.

### U19: потеря связи — телефон

1. Запусти launcher без --web, телефон и ПК в одной Wi-Fi сети, подключись через Expo Go и адрес из файла подключения.
2. Запиши суммы. Отключи Wi-Fi телефона, вызови загрузку данных: ожидается понятная ошибка и возможность повторить.
3. Восстанови сеть → Try again: те же финансовые данные. Не отмечай PASS только по наличию старого кэшированного экрана.

### U20/U21: экран и доступность

1. На телефоне открой длинную форму Balance & bills; вызови клавиатуру в нижнем поле и прокрути до Save. Кнопка доступна, суммы и даты читаемы.
2. Измени поле и выйди Back: скрытого сохранения нет.
3. Повтори при увеличенном системном шрифте, светлой/тёмной теме и с TalkBack/VoiceOver. Основные кнопки имеют понятные названия, порядок фокуса логичен; ошибки доступны текстом.
4. Проверка узкого браузерного окна полезна, но не подтверждает поведение нативной клавиатуры и screen reader телефона.

### U22: импорт и ошибки файла

1. Upload statement → синтетический `docs/testing/sample-statement.csv`: при чтении виден Reading statement, кнопка повторной загрузки выключена.
2. До Save запиши/сверь прежнее состояние. Preview ожидается 3 / income 600 / spending 35.
3. Отдельно выбери заведомо не-выписку или повреждённый тестовый файл без личных данных. Ожидается сообщение, состояние не меняется; после ошибки можно выбрать корректный CSV.
4. Для долгого импорта нужен достаточно большой синтетический файл в допустимом лимите; мгновенная обработка маленького CSV не доказывает устойчивость долгой загрузки.

## 5. Режим AI и известные ограничения

Настоящий AI проверяется отдельным запуском `start-vela.cmd --web --ai` с настроенным ключом и расходует квоту. Повтори вопросы §10 USER_MANUAL, проверяй источник ответа и актуальные суммы. Не считай offline 60/60 результатом живого Gemini.

Learn пока не имеет перехода из основных вкладок; прямое открытие web-маршрута может оставить Loading после потери подключения. Это известный блокер, результат ручного обучения пока не PASS.

## 6. Запись результатов

Для каждого пункта запиши: ID; дата; версия/коммит; Windows/Android/iOS и браузер; local/AI; путь тестовой базы; начальные суммы; точные действия; ожидание; факт; PASS/FAIL/BLOCKED/NOT RUN; снимок без секретов. Частично выполненный сценарий пометь PARTIAL с оставшимися шагами.

Не объединяй результаты API, web и телефона в один PASS. В MANUAL-02 U04 проверяет только создание плана, U05 — одно выполнение и исчезновение кнопки; отмена и быстрый двойной клик требуют отдельных прогонов выше.
