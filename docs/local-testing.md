# Локальная проверка Vela: backend + Expo

После запуска используй [пользовательский мануал](USER_MANUAL.md): кнопки, контрольные суммы и чеклист U01–U22. Тестовый CSV находится в `docs/testing/sample-statement.csv`.

## Запуск

Из корня проекта:

```powershell
.\start-vela.cmd
```

Либо двойной щелчок по `start-vela.cmd`. Он использует `.venv`, если она есть, иначе Python из PATH. Скрипт проверяет зависимости и свободные порты, запускает API, проверяет запрос с авторизацией и запускает Expo в режиме Expo Go с QR-кодом. Существующая `.env` сохраняется; при её отсутствии используется `scripts/setup-local.py`. Ничего не устанавливается автоматически.

Телефон и компьютер должны быть в одной доступной Wi-Fi/LAN-сети. Открой QR-код через Expo Go. На экране Connect Vela введи API address и Access token из `.local/dev-connection.txt`. Этот файл локальный и игнорируется Git; не отправляй его в чат. Токен не встраивается в приложение. Если Windows запросит доступ Python/Node к сети, для телефона нужен доступ в доверенной частной сети; скрипт не меняет firewall.

Для проверки в браузере:

```powershell
.\start-vela.cmd --web
```

Адрес браузера: **http://localhost:8081** (именно localhost, он разрешён CORS). API: `http://127.0.0.1:8000`. Web-версия позволяет проверить UI/API, но не заменяет проверку нативного импорта и поведения телефона. В web после обновления страницы подключение вводится снова — текущее ограничение клиента.

Нажми **Ctrl+C в окне запуска**, чтобы остановить оба сервиса. Не закрывай окно крестиком, если нужна контролируемая остановка. Сохранённые данные `.local/demo.db` остаются. Повторный запуск ничего не сбрасывает и не подгружает demo-данные без твоего действия.

## Варианты

```powershell
# Диагностика без запуска и без изменения .env
.\start-vela.cmd --check

# Проверка для агента: поднять API/Expo, проверить, остановить оба
python scripts/start-dev.py --smoke

# Выбрать Wi-Fi IP, если VPN/несколько адаптеров мешают автоопределению
.\start-vela.cmd --lan-ip 192.168.1.25

# Если на устройстве уже установлен development build
.\start-vela.cmd --dev-client

# Явно включить Gemini из локальных настроек (расходует квоту провайдера)
.\start-vela.cmd --ai
```

По умолчанию Gemini отключён только для запущенного процесса; файл `.env` не меняется. Чат использует локальный fallback. CSV/XLSX и локальные ветки разбора доступны, но AI-зависимые PDF/изображения и ответы Gemini требуют `--ai` и настроенного ключа. Это не полноценный тест качества модели.

Проект использует Expo SDK из `apps/mobile/package.json`. Если установленный Expo Go сообщает несовместимость, используй совместимый клиент или установленный development build; скрипт не понижает SDK и не собирает/публикует приложение. Expo tunnel здесь не включается: туннель только для Metro не откроет телефону локальный API.

## Если запуск не удался

- Порты 8000/8081 заняты: останови прежний запуск. Скрипт не убивает чужой процесс и не выбирает незаметно другой порт.
- Нет Python-зависимостей: в выбранном окружении установи уже объявленные `services/api/requirements-dev.txt`.
- Нет `node_modules`: выполни `npm ci` в `apps/mobile` (используется существующий lockfile).
- Сервер не стартует: смотри `.local/dev-api.log`.
- Expo не стартует: вывод в терминале; при `--smoke` — `.local/dev-expo.log`.
- Телефон не подключается: проверь Wi-Fi, выбранный IP, VPN и доступ Python/Node в частной сети. `127.0.0.1` на телефоне означает сам телефон.
- Ошибка токена: открой локальный файл подключения и скопируй значение заново. Существующий короткий/шаблонный токен не заменяется молча.

## Первый пользовательский прогон

1. Подключиться; создать тестовый профиль или вручную выбрать доступный demo-сценарий.
2. Проверить Today: баланс, обязательства, цель, объяснение доступной суммы.
3. Добавить действие в My Plan, изменить сценарий суммы, отменить/подтвердить тестовое действие.
4. Импортировать синтетический CSV, проверить превью, затем повторить импорт и проверить отсутствие дублирования.
5. Открыть долги и уроки; задать вопрос ассистенту, учитывая local/AI режим.
6. Перезапустить оба сервиса и убедиться, что финансовые данные сохранились.
7. Экспорт/удаление проверять только когда готов удалить текущие локальные тестовые данные.

Это проверка локального однопользовательского прототипа, не приёмка T24b, не CHECKPOINT-2 и не подтверждение production-ready. Фиксируй экран, шаги, ожидаемое/фактическое поведение; токены и реальные выписки в отчёт не вставляй.

## Инструкция агенту

Запускай из любого cwd через абсолютный путь к `scripts/start-dev.py` выбранным Python либо корневой CMD из Windows. Для автоматической проверки используй `--check`, затем `--smoke`; оба возвращают ненулевой код при ошибке. Smoke проверяет готовность API/Metro, но не компиляцию всех экранов и не E2E. Для пользовательской сессии запусти обычный launcher в интерактивном терминале, оставь его открытым и сообщи путь к файлу подключения. Не выводи файл с токеном в tool output. Не сбрасывай БД, не вызывай `/v1/demo`/удаление и не включай `--ai` без запроса. Остановка smoke выполняется автоматически; пользовательская — Ctrl+C.
