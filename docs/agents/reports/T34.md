## Delivered

`PrivateStorage` requires explicit30-day retention consent before writing bytes/metadata. Filenames are validated but not retained/used as paths/logs. Random UUID file IDs plus hashed owner components identify objects. SHA256 and size are verified per read, with exact-expiry/status checks before provider I/O. Pending/deleting/expired originals never become readable because physical deletion failed.

Local objects are isolated outside webroot, with bounded reads/path/symlink-escape checks. Cloud objects use trusted Supabase HTTPS origin/private bucket and a backend-only credential, checking bucket private state before read/upload. Read uses authenticated object route, no public/signing URL; redirects/proxies are disabled and provider errors sanitized. Both missing storage settings yield explicit unavailable cloud storage (never filesystem fallback); partial configuration fails startup. All provider tests use MockTransport; no live key/project/connection.

Durable `private_original` metadata stores owner/file ID, nonsecret backend target identity, opaque object key, digest/size/timestamps/status. A target fingerprint binds resolved local root or Supabase origin+bucket: wrong-target404 cannot silently erase metadata while old bytes remain elsewhere. Credential rotation preserves target identity. New frozen0002 revision adds this table; version-aware env validation preserves immutable0001 and exact five-table legacy payloads. Existing migration tests retained with only justified expected-head update.

Metadata records pending intent before upload; failed/lost upload response retains cleanup intent. Activation uses pending→ready CAS. A second Store deleting a pending upload during external I/O cannot cause false-ready success: missing/changed activation restores durable cleanup intent before compensating delete, retaining retry state if compensation fails. Full account-generation/worker/crash/restore lifecycle remains T33/T62, and earlier deletion may precede completion of in-flight provider upload; no immediate global physical-erasure guarantee.

Authenticated `GET/DELETE /v2/originals/{file_id}` enforce owner-bound reads/deletion; download uses fixed filename/octet-stream/no-store. Account `DELETE /v1/data` erases original financial entities as before; original cleanup failures preserve denied durable metadata and return202 `deletion_pending` with count rather than false complete deletion. Retry finishes cleanup. No public erase-all endpoint; internal erase-all requires explicitly disposable local fixture.
