## Что сделано

- Authenticated GET `/v2/frontend` projects personal data, one canonical plan, recorded activity, suggested observations and contextual lessons from exactly one stored state/revision. GET `/v2/assistant/context` exposes the same read-only structured facts. No second financial state or AI-generated money is introduced.
- Capabilities explicitly identify local single-user mode, EUR planning, separate EUR/HUF accounts and analytical-only imports. Cloud OTP, owner isolation, persistent chat, server reminders, bank connection, transfers, multiple goals and plan FX are unavailable, not falsely implemented.
- POST `/v2/planning/resume` complements defer with existing revision/idempotency handling. Existing preview remains read-only. Financial rules and the provisional suggestion policy are unchanged.
- Optional exact frontend-origin allowlist preserves previous default CORS origins. Rejects credentials, wildcard, null, paths, query/fragment and malformed port before storage creation.
- Framework-independent ES-module client wraps bootstrap/current context, accounts/income/planning lifecycle/bills/import/evidence/lessons/export/delete. Prepared write captures immutable body/key so retrying an uncertain response does not create another command. No automatic conflict revision replacement. Non-JSON errors preserve status for UI failure handling. No dependency or credential persistence.
- One-command launcher uses a held OS-assigned loopback socket, unique ignored synthetic database/quota directory, private connection file and forcibly disabled AI; it never loads .env or an existing database. `--empty` selects onboarding instead of the seeded example. The previous autonomous HTML is unchanged and disconnected.
- Added `FRONTEND_INTEGRATION.md` with local connection instructions, code example, full screen/button/API mapping, amount/date/currency/unknown rules, confirmation/retry/conflict handling and unsupported-feature boundaries. Clarifies that prompt EUR40 is an explicitly chosen example, not a change to the existing initial EUR20 suggestion.

## Риски и известные ограничения

- This is a local integration kit, not full cloud backend completion or release acceptance. Actual OTP/JWT owner isolation, migrations, durable document jobs/corrections, persistent conversations, multiple goals, recommendation ID/version publication and cloud account deletion remain their existing tasks/gates.
- Server date/freshness rules remain authoritative; a prior-day synthetic plan needs balance reconfirmation. Recorded-activity totals are the latest recorded30-day window, not necessarily the current calendar month; zero without transactions does not establish no spending. Observations may span a longer recorded period.
- Local token remains one synthetic owner; CORS is not a substitute for authentication. Launcher is loopback-only; hosted HTTPS builders should export/run locally rather than expose or tunnel this API.
- SDK amount inputs are validated by server schemas; UI formatting and confirmation/accessibility states still belong to the frontend. Export acknowledgement does not prove browser file save; local erase does not revoke development token.
- No native/owner UX/cloud/paid/live-AI/deploy evidence claimed. demo.db, APIs8000–8003 and autonomous HTML were not read/changed/contacted by this executor.
