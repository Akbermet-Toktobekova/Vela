# Report T20 — Защита CSV от формульных инъекций

- **Status:** review

- **Attempt:** 1

## Что сделано
- Создан модуль `services/api/vela/csv_safe.py`, реализующий защиту от CSV/DDE Formula Injection:
  - Определён список опасных префиксов: `DANGEROUS_PREFIXES = ("=", "+", "-", "@", "\t", "\r")`.
  - Реализован строгий распознаватель чистых чисел `is_pure_number(value)` для сохранения отрицательных и положительных финансовых сумм (`int`, `float`, строки вида `"-150"`, `"-12.50"`, `"-19,99"`, `"+100"`).
  - Реализована функция `escape_cell(value: Any) -> str`:
    - Проверяет значение на наличие опасных префиксов как в начале, так и после ведущих пробелов (`" =cmd|..."`).
    - Если префикс опасный и значение не является чистым числом, экранирует префиксом `'` (апостроф).
    - Чистые отрицательные и положительные финансовые числа остаются неизменными (не превращаются в текстовые `' -150`).
    - Обычные строки, даты и `None` корректно конвертируются без искажений.
  - Реализованы вспомогательные функции пакетного экранирования `escape_row(row)` и `escape_table(rows)`.
  - Реализована функция `format_safe_csv(rows, ...)` для безопасного форматирования CSV по стандарту RFC 4180 с использованием встроенного `csv.writer(..., quoting=csv.QUOTE_MINIMAL)`.
- Создан тестовый набор `services/api/tests/test_csv_safe.py` (7 тестов `unittest.TestCase`):
  1. `test_all_six_dangerous_prefixes_are_escaped`: проверка экранирования всех 6 префиксов (`=`, `+`, `-`, `@`, `\t`, `\r`).
  2. `test_pure_negative_and_positive_numbers_preserved`: сохранение отрицательных (`-150`, `-12.50`) и положительных чисел без апострофа.
  3. `test_arithmetic_or_command_strings_with_plus_or_minus_are_escaped`: экранирование выражений вида `"-2+3"`, `"+cmd|..."`, `"-cmd|..."`.
  4. `test_ordinary_strings_and_dates_untouched`: проверка обычных строк, дат и `None`.
  5. `test_leading_whitespace_formula_injection`: нейтрализация формул с предшествующими пробелами (`" =cmd"`, `" \t+1"`).
  6. `test_escape_row_and_table`: корректная пакетная обработка строк и матриц данных.
  7. `test_format_safe_csv_output`: проверка результирующего RFC 4180 CSV-текста.
- Точки интеграции в `main.py`:
  - В настоящее время `services/api/vela/main.py` содержит только JSON-экспорт (`GET /v1/export`).
  - При реализации CSV-экспорта (например, `GET /v1/export/csv` или `GET /v1/transactions/export`) необходимо использовать `format_safe_csv(rows)` перед отправкой в `StreamingResponse(content, media_type="text/csv")`.
  - `main.py` оставлен без изменений, чтобы соблюдать принцип минимального скоупа и отсутствия преждевременных неспецифицированных эндпоинтов.
