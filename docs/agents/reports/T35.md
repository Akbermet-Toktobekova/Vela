## Changes

Added standard-library JSON request logging and pure ASGI correlation middleware. Every HTTP request gets an isolated ContextVar/request.state correlation ID. A supplied canonical UUID or16–64 hexadecimal opaque ID is accepted; missing, malformed, duplicate, overlong or free-text/PII-bearing IDs are replaced with UUID4. Returned HTTP response-start headers include X-Correlation-ID, including handled401/422/409/404 and CORS responses. A per-app unexpected-Exception handler supplies a generic500 JSON response and the same correlation ID retained in request.state after context reset. CORS registration allows and exposes this header for explicitly allowed browser origins.

Only six fields are serialized: constant event `http_request`, correlation_id, bounded method, registered route template (or unmatched), status, duration_ms. No raw URL/path parameters/query, request/response body, token, transaction label, financial sum, arbitrary message/extra field, exception text or traceback is serialized. A dedicated filter discards arbitrary event types and clears free-text message/exception content; the formatter independently uses an explicit field allowlist. Current-context reset is in a nested finally block even when app/log emission fails.

Each factory creates a private logging.Logger and handler; no global root logger, basicConfig, uvicorn configuration, logger registry or other tests' handlers are reconfigured. The middleware neither reads request bodies nor changes financial commands, database schemas, policy or API response models. Non-HTTP/lifespan scopes pass through unchanged.
