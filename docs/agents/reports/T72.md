## Delivered

New authenticated POST /v2/imports/{id}/apply accepts only expected revision plus Idempotency-Key. It merges historical transactions without creating/changing profile, cash, savings, obligations, debt, actions or deferred status. No hidden goal/buffer on first import. Exact retries return their receipt; revision conflicts reject stale writes. Refuse over3000 unique rows before mutation rather than dropping older records. Original /v1 apply is retained for legacy clients; its financial-mutating behaviour is NOT the new contract and no longer appears in the import UI.

Import UI now uses /v2, explains historical balance/no financial mutation, separates labelled refund credits and net spending, removes current-balance replacement and bill-creation controls, and paginates all preview rows. Explicit refund descriptions are suggested refunds, not salary. Old imported income/other refund labels upgrade only during a new analytical-apply command, preserving original amounts/dates/descriptions. Other stored categories are preserved. Imported future credits cannot fund legacy plan capacity. Tools separate income/refunds and retain true net cash flow.

GET /v2/observations analyses the complete retained history deterministically, without AI: possible recurring same-calendar-day payments with one entry per recorded month, observed charge changes, income series, recorded monthly category debits, explicit-reference refund candidates and transfer-labelled evidence. Every item has suggested status, method version, stable ID, source transaction IDs and periods; no confidence scores, financial thresholds or motives invented. Partial coverage and unconfirmed ownership are explicit. No observation creates a bill or money action. Pattern decisions/rejections are not yet persisted; analysis is recomputed cheaply on read, not a worker/publication implementation.

New /observations screen is reachable from saved accounts/Today, supports source evidence and paginated full transaction history without a goal or legacy snapshot. Legacy My Plan history also paginates beyond50 with errors visible. /v1/transactions gains backward-compatible offset. Currency-column detection preserves a single explicit currency; /v2 refuses non-EUR/mixed-currency analysis instead of converting to EUR. HUF account support is unchanged; HUF/FX analytical integration remains pending.
